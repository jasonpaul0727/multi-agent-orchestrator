# P3 supervised systemd transport addendum

Status: design for independent review; v2 remains disabled until the staged implementation and acceptance checks pass. This addendum refines Task 3 and Task 2 C2a of the mediation stop-proof design; it does not change v1 semantics or grant execution authority. A transport experiment is not a production stop proof.

## Objective and evidence boundary

One owned supervisor must control each v2 actor's only launch transport from durable prelaunch permit through exact stop. A successful terminal decision requires a closed, complete actor census, authenticated identity and authority, known Provider outcome and settlement, exact actor stop, and proof that no admitted transport can subsequently submit that actor. A missing unit or cgroup, a dead PID, an empty snapshot, a timeout, lost connection, or a host-supplied Boolean proves none of these. A result that cannot be established remains held. No unknown Provider operation is resent.

A local experiment has confirmed this host's manager can receive three file descriptors and return a matching successful JobRemoved. It has also shown that the existing `systemd-run --collect` path may leave no unit or cgroup after exit. These observations are environment-specific, not a compatibility guarantee. The sandbox fixture validates only two fixed sockets and one cgroup path, not arbitrary host isolation, manager authentication, FD forwarding, or stop proof. Runtime support must be checked; failures hold.

## Trust root and durable admission

The trusted host includes configured host processes under the same UID, the orchestrator, broker and manager. They are assumed not to maliciously interfere with authority, dispatch, manager, store or cgroups; accidental races, duplicate requests, stale state and crashes remain in scope. Workers, executed tools, injected components and external input remain untrusted regardless of UID. UID is not authorization: sandbox confinement must deny them bus, manager socket, broker capability, store and cgroup control, and a host-controlled protocol must authorize component role and request. Other UIDs and unauthorized processes must be excluded by the deployment boundary; administrators/root can override it and are trusted operationally. Broker, manager, kernel or trusted-host compromise is outside this guarantee. Verify actual confinement on each supported profile or deny v2.

The host-owned supervisor binds trusted configuration, opened store identity, host, boot, manager unique owner and broker instance using host and kernel/manager observations, never Worker input, caller receipts or hashes alone. Protect the executable, configuration, store and manager from actors outside the trusted host boundary. A shared same-UID user manager is acceptable under this assumption, but random names are not authority and unaccounted legitimate host actions invalidate continuity. Root and shared dependency installation are not assumed.
Permit creation uses one owned SQLite write transaction and a single lock-time clock sample. Verify current Scheduler admission, attempt and fencing generation, same-store host root and applicable policy/grant, the complete bounded v1/v2 gate, operation identity, open status, and the canonical broker-prepared actor. Atomically append a *trusted-provenance-versioned* permit, reserve its future evidence capacity, and insert a unique canonical `(host, boot, unit)` key, `(host, boot, launch_id)`, `(operation, actor_id)` and `(operation, sequence)` constraints. The exact validated manager namespace is part of host authority; unit canonicalization and aliasing must not admit two names for one unit. Unique rows, event/version, admitted identity and run-scope indexes must agree in both directions under bounded reads; a missing, orphaned, duplicated or inconsistent record holds. No migration infers trusted provenance from old inert `Permitted` records; those streams remain inert and cannot be upgraded in place. An explicit versioned path must either establish a fresh eligible operation with independent authoritative inputs or hold; never reinterpret history.

Close uses the same write lock. If permit commits first it is in the frozen census, including a permit whose broker has not started; if close commits first the permit fails. Authentic late ACK/stop for a pre-close permit may consume its reserved space. The broker may cross a launch boundary only after commit is known; ambiguous commit or a replayed permit does not mint a new start opportunity. Each permitted actor remains `launch_unknown` until authentic evidence resolves it. Existing close, cancellation intent and v1 behavior remain available without allowing terminal release on unknown evidence.

A capacity reservation must include all mandatory permit, ACK, stop, transport, close and seal records with bounded serialized bytes and index overhead. It must cover late evidence after close and cannot be stolen by another actor or operation. The cancellation proof has a run-wide 4 MiB / 4000-row budget shared with lifecycle, v1, linked Provider, budget, artifact and Scheduler evidence. Count the actual indexed preflight and replay accounting, including twice-read event rows, version probes and metadata; enforce bounds before decode and before admitting a permit. At 128 actors, 387 events require at least 775 charged rows for one full stream, and 387 × 16384 = 6,340,608 payload bytes before envelope overhead; these maxima cannot be promised within the existing run budget. The implementation must set smaller proved per-record and per-run reservations or explicitly deny further permits while retaining room for all previously reserved late evidence. A theoretical reservation is insufficient unless the cancellation proof actually consumes those bounds. Unknown/corrupt/over-budget histories remain cancelling with redacted reasons, not falsely stopped. No claim bounds SQLite page I/O, CPU or unrelated legacy outer work.

Checkpoint initialization must scan all physical rows independently of version metadata and validate every publication's v1 business fields, including earlier records; stricter rejection of malformed later publications has the compatibility cost stated in the mediation design. Shared artifact histories are not bounded by per-run reservation: use the conditional checkpoint and operation-scoped capture requirements in the mediation design's “Bounded shared artifact evidence” section. Until their writer coverage and proof budget are established, unknown or oversized shared digest history holds; do not block unrelated digests or promise arbitrary future digests.

## Supervisor and durable state machine

An independently hosted supervisor owns its bus connection, exact manager owner, request ledger, pipe ends and actor/session identities. It serializes messages for each permit and will issue at most one `StartTransientUnit` for its unique unit. It may not accept a request from an untrusted Worker or use caller-supplied launcher, manager path, receipt or component as authority. A process-local supervisor may implement a first experiment, but process-local state is not restart proof. Broker availability and isolation are prerequisites to production authority.

Durable states, each bound to operation/fence, actor/sequence, prepared parameters digest, host/boot/store, manager owner and unique unit, are:

1. `PERMITTED`: permit and evidence reservation committed. No launch may occur without this row.
2. `START_DISPATCHING`: before any bus write, persist the exact one-shot dispatch intent. This marks the outcome potentially delivered; a crash or timeout after it never permits retry. Record a broker epoch and connection identity. A failure before the first write may only become no-start with a separately designed and trusted irrevocable fencing proof; initially it remains unknown.
3. `START_PENDING`: a send may be delivered. Retain the bus connection and subscribed job listener; persist the request association when available. A method reply only identifies an enqueued job, not successful start. Match exact job path, unit and `done` result. A negative result must not be recast as a no-start proof without further evidence.
4. `ACKNOWLEDGED`: only after the matching start job succeeded and trusted manager observations bind the exact original unit, invocation, profile, cgroup and boot to the permit. Persist the authentic ACK. Failure or crash before durable ACK remains launch_unknown even if a unit appears absent.
5. `STOP_REQUESTED`: serialize with start ownership. Stop may be requested while start outcome is unknown, but must not assert no future start. Continue resolving the original start on the same supervised connection; any stop job is matched to its exact path and owner. Do not call StopUnit once on timeout, kill the subscriber and treat absence as stopped. A queued or manager-accepted start may run after such a stop. If start can still complete, retain the listener and fence the start transport, then issue or repeat a correctly correlated stop only when ordering establishes that no earlier start remains capable of execution.
6. `STOPPED`: only after the authenticated start request has resolved, the broker proves no additional start can be submitted for this unit, a stop or naturally completed unit is bound to the ACK and a matching manager result establishes terminal processing, and independent cgroup proof below establishes no surviving descendants. All records must be persisted and cross-checked before release. A job completion alone is not cgroup proof; a locally stopped sender does not establish Provider outcome or usage.

`UNKNOWN` is a durable held outcome for unresolved dispatch, response, job, identity, evidence, capacity, policy or transport. It must never transition to stopped based on time, absence, PID loss, or caller assertion. Safe authentic late evidence can resolve an existing actor; conflicts or provenance mismatch hold.

A timeout requests cancellation and records an unresolved deadline; it does not kill the supervisor, unsubscribe, destroy pipes, release reservations, or synthesize no-start. The supervisor keeps processing manager replies and job signals with bounded resources. On manager disconnect, unique owner change, signal loss, buffer overflow, malformed data or uncertain ordering, evidence is unknown. `Subscribe` and signal match are installed before starting; buffer early JobRemoved signals, then correlate with the returned job object and expected unit, sender/manager owner and result. Duplicates must agree; unknown or missing signals cannot be inferred away. The connection must not be shared with unrelated callers and must not submit a second start. Resolve the effect of any sent method before claiming transport quiescence. Bus connection closure or death alone does not prove the manager discarded a previously accepted request.

An orchestrator restart can reconnect to a still-running authenticated supervisor and read its durable state; it does not issue a new start. A supervisor or manager crash, lost broker state, lost boot/store identity, incomplete request/job record, or unprovable manager continuity holds across restart. Any later recovery protocol must demonstrate message-queue and manager ordering, broker ownership and durable evidence; the first implementation may simply hold. Same host and boot are mandatory, not sufficient. No restart or cleanup process may revive the dispatch opportunity.

## Pipe and process transport

Worker stdin carries the original request; stdout carries proposals and stderr is separately captured. The supervisor owns three separately tracked descriptors and retains existing output limits, deadlines and cancellation behavior. It must actually pass the correct three FD ends into the transient service; `StandardInput=fd:name` by itself refers to a named socket-unit descriptor and is not evidence of arbitrary FD injection. Any transient FD setter, D-Bus `h` encoding and descriptor ownership is version-checked and integration-tested on the target manager; unsupported settings fail closed. A local ctypes sd-bus binding, if used, declares the exact ABI, non-variadic message containers and pointer types, pins callback/userdata lifetimes, manages all bus/message/slot/FD references, validates manager identity, and treats every error or ambiguous close as unknown. Library presence and FD negotiation do not prove successful descriptor passing.

Drain stdout and stderr concurrently while writing stdin, using nonblocking I/O and bounded buffers, so 512 KiB or larger than pipe capacity in all directions cannot deadlock. Preserve byte identity, independent EOF, backpressure and output caps; close each redundant end at the right time without closing a still-needed inherited endpoint. Resource cleanup cannot be mistaken for unit or transport stop. Supervisor failure during data exchange leaves the permitted actor held. A controlled IPC forwarding process is acceptable only after equivalent identity, backpressure, cancellation and lifetime properties are demonstrated.

## Exact unit stop and cgroup evidence

The broker must have an authenticated ACK for the original invocation and prevent unit reuse, automatic restart, dependency-triggered starts and competing manager clients under the host trust root. Match the stop job and manager owner to that invocation; neither a manager query nor repeated samples create an atomic lock on external state. A same-name unit with a different invocation, a change in manager owner, an inaccessible profile or an unverified control group holds. Unit disappearance or blank ControlGroup after collection is not evidence of an empty group.

The system needs an actor-specific, host-owned cgroup subtree whose stable identity is retained independently of the unit, with enforceable containment preventing untrusted actors from moving themselves or descendants out. After the manager has resolved the start and stop ordering, inspect a still-existing, identity-checked cgroup v2 subtree and require authoritative `cgroup.events` `populated 0`, accounting for descendants. Establish correct mount, device/inode, host/boot, permissions and lifecycle before launch, and validate them again when collecting proof. Before launch retain anchored no-follow directory and events FDs, binding mount ID, device and inode to host/boot. At proof time compare retained identity with a fresh anchored reopen, read populated from the retained events FD, then revalidate identities before publication. Rename, deletion, replacement, failed reopen or mismatch holds; an FD for an unlinked old subtree is insufficient. A missing, replaced, unreadable or unauthenticated cgroup is unknown, not empty. An open directory FD alone does not guarantee that systemd preserves the subtree; a sentinel inside the measured subtree would itself prevent `populated 0`. The design must demonstrate an actually persistent, independently controlled subtree and exclusive authority, or fail closed. If unprivileged manager and cgroup delegation cannot provide those properties, this deployment cannot enable this v2 stop proof. Multiple samples do not repair the absence of an authority that excludes future starts or migration.

## Host root, producer exclusion and one-shot dispatch

These constructions are prerequisites, not claims about the current host. Validate configured executable, configuration, opened store and manager namespace at startup; bind store, host and boot to the manager unique owner tracked on an authenticated connection. Mismatch holds. Trusted same-UID host processes may share the manager, but must follow producer ownership; unexpected competing actions invalidate continuity. No isolation against their malicious actions is claimed.

Authenticate a reconnecting orchestrator as an authorized host component using a host-controlled endpoint, kernel peer credentials and per-instance inherited capability or equivalent host-controlled registration. UID is an admission check, not authorization for every same-UID process. Bind role, epoch, store, operation and request identity and reject replay. Workers and tools must not acquire the endpoint or capability; inability to verify confinement or registration holds. Broker compromise is outside this design.
The broker creates an unforgeable, nonserializable, live one-shot dispatch capability for a newly admitted actor in its own epoch. The capability is bound to the exact committed permit event, operation/fence, actor, unit, store, manager owner, broker epoch and reserved evidence. The broker must re-enter the same owned SQLite write lock immediately before dispatch, check the exact committed permit, open/closed state and revocation/current authority, and durably record the unique dispatch intent. If close or revocation wins that lock, dispatch is refused; if dispatch wins, that actor remains in the frozen census and a later close or revocation requires stop handling. The live capability is consumed at most once by the owning broker, and only after the dispatch-intent commit is positively known. A lost commit response, uncertain transaction, connection failure, broker restart or capability loss holds; querying a durable intent or replaying IPC must never recreate send authority. Exact idempotent reads may return history but cannot mint a capability. The transition must be protected against two live brokers by an independently authenticated exclusive epoch/lease whose loss is checked under the same ownership boundary. Use an OS-held exclusive broker lock and durable unique dispatch intent in the same SQLite transaction; do not transfer on a timer. A new owner may acquire the lock but existing intent never grants another send. If ownership or commit outcome is uncertain, neither sends. A lease timeout or disappearing process alone does not prove a previous broker or manager request cannot act.

Tests must exercise two real broker processes with barriers at transaction acquisition, dispatch commit, before bus send and after send, including close/revoke winning each side, duplicate IPC, conflicting broker epochs, response loss after commit and broker crash. Observe actual manager submissions and assert at most one, no submission when close/revocation won, and held state for ambiguous outcomes. A test double or a database uniqueness constraint alone is not proof of exclusive live authority.

## Stable ownership and control-plane confinement

The exclusive broker lock has one configured canonical namespace for every broker sharing the store and manager. Open its trusted stable directory by anchored, component-by-component no-follow traversal; validate owner, permissions, filesystem and directory identity. Open the lock without following links and bind its device/inode and mount identity to that namespace. While holding the lock, verify the retained descriptor and a fresh anchored reopen have the same identity before dispatch and throughout proof publication and release. Never unlink, rename or replace the lock file or a parent while the installation is active. Detect missing, replaced or inconsistent identities and hold; a process holding an old inode does not exclude a process locking a replacement. All participating brokers must use the same namespace and locking protocol. Verify cross-process exclusion, SIGKILL and restart semantics on the actual supported filesystem and mount before enablement. SQLite DB, WAL and SHM must reside on a supported filesystem with working cross-process SQLite locking and crash-durable commit, verified for the deployment; unsupported, I/O error or uncertain commit holds and cannot authorize a send. Host power loss durability cannot be inferred from process-kill tests.

A local WSL /mnt/c drvfs/9p spike observed same-inode flock exclusion between two processes, reacquisition after holder SIGKILL, and O_NOFOLLOW rejection of a symlink. Replacing the lock inode let a second process acquire a new lock while the old holder still lived, demonstrating split ownership. SQLite BEGIN IMMEDIATE exclusion was observed only between two connections in one process; cross-process locking, power-loss durability and Windows-native access were not tested. These observations are specific to that mount and are not production prerequisites proven, authority, or stop proof.

Inside each broker, serialize capability validation, atomic consumption, and the first bus send through a single-threaded event loop or a lock held across the whole transition. No other thread or asynchronous callback can dispatch the same actor; cancellation of await or to_thread does not recall a delivered request. Timeout or cancellation after possible delivery remains unknown until the original request and job are resolved. Test same-broker thread and async races as well as two independent broker processes, including cancellation at each boundary and observed actual submission counts.

Control-plane capabilities and descriptors are close-on-exec and never inherited by a Worker or tool, including via standard streams or a transferred socket; close unused ends and verify child FD tables and actual access. External input and all child IPC are data only: they cannot select or assert role, permit, unit, launcher, policy or stop evidence. Test a restricted same-UID Worker attempting forged and replayed requests, guessed endpoint access, inherited and transferred FD leaks, and unauthorized role claims; failures hold rather than authorize.
## Queue closure, continuity and bounded uncertainty

For each actor the broker maintains a continuity epoch starting before signal subscription and lasting through evidence publication. An irreversible queue-closure gate may be asserted only if the trusted producer is exclusively controlled, the one permitted start was fully resolved with its matching manager job and exact ACK, all requests that can affect the unit are accounted for, and no producer can submit or cause another start. The gate binds permit, ACK, unit/invocation, manager owner, connection and broker epoch, exact start and stop jobs and the cgroup identity. It must prohibit or conclusively account for unit aliases, restarts, timers, sockets, paths, dependency activation and any other start producer. Manager replies, signal subscriptions, a connection close, or repeated absence samples alone do not establish queue drainage or prevent future producers. The enforcement mechanism is an implementation prerequisite to demonstrate, not an existing facility assumed by this design.

The same live broker must continuously hold its verified producer ownership from before the final cgroup observation through evidence commit and the subsequent release decision. Its serialized event stream must account for manager owner, relevant jobs, unit identity and cgroup lifecycle; any unexpected producer action, replacement, ownership loss, event loss or uncertain ordering synchronously invalidates the epoch and prevents both commit and release. The release path must consume the same still-valid epoch under an ownership protocol that cannot race invalidation: serialize event handling, final validation, commit and release decision in the broker, with invalidation made visible before a competing release can succeed. If the implementation cannot establish that continuity and ordering across the external observation and both SQLite transactions, it must hold. Repeated samples and a database lock alone cannot close this external-state window. On broker crash or inability to establish continuity, persisted observations do not recreate the epoch.
Publish stop authority only when that still-valid gate, the corresponding exact stop job or proven natural termination, and the retained cgroup proof are joined in one owned transaction against the unchanged frozen census and authority. Recheck the continuity epoch and all durable identities at publication; a transaction can serialize local decisions but cannot make external systemd samples atomic. Loss of broker/manager continuity, an unaccounted message or producer, conflicting job/ACK, a replaced unit or cgroup, or inability to establish exclusive producer control invalidates the gate and leaves held. Reacquiring a connection or observing an empty group does not recreate continuity. A later recovery protocol needs its own proof of queue closure and exclusivity; initial recovery holds.

Timeout handling has explicit bounded resources: configure finite per-actor and per-run limits for pending operations, buffered manager signals, queued bytes, pipe bytes, file descriptors, and active supervisor lifetime, plus a finite deadline for draining and reconciliation. Values must be chosen and tested before enablement and must fit the run-wide evidence and cancellation budgets. A deadline requests stop and continued bounded supervision while resolving a possibly delivered start. On a bound being reached, persist redacted durable unknown and retain its reserved evidence before closing any supervised resources; if that durable write is uncertain, the pre-existing permit itself remains unknown. Controlled shutdown may close the bus, pipes and process after this durable hold, but closure is not evidence that a manager-accepted start was discarded, that any actor stopped, or that the queue is sealed. No retry, release or completion is authorized. If even durable unknown cannot be written, fail closed using the existing unresolved permit; never require an unbounded listener as the condition for safety.

Acceptance tests must inject an early matching signal, absent/duplicated/conflicting signals, unrelated manager owner, owner replacement, delayed start completion after timeout and after a stop request, and competing start producers including aliases, restart policies, timers, sockets and dependencies. Verify exact job association and that any lost continuity or unaccounted producer remains held; test signal-buffer and FD limits, safe shutdown and restart with durable unknown. A successful test on one manager does not establish confinement or continuity for a different environment: each production admission and release must verify its current prerequisites.
## Staging and acceptance

All real systemd starts before trusted same-store policy and revocation authority is implemented are restricted to controlled test fixtures and do not constitute v2 admission. Production v2 admission remains denied until Task 4 policy/revoke is checked under the same owned lock as dispatch authority.

1. Keep v1 and its current default start/recovery/stop semantics unchanged. Add disabled experiments with no journal authority. Exercise real independent sd-bus transport, subscribe-before-dispatch and three FDs; check feature/ABI support. Failed capability checks do not enable v2.
2. Before durable permits or broad migration, run a low-cost, non-authoritative capability spike on the target environment: verify manager identity, sandbox denial of bus, broker, store and cgroup control, and actor parent-subtree persistence, identity, delegation permissions and migration resistance through actual start/stop and collection. If confinement, stable containment or an authenticated host root cannot be established, v2 remains disabled and any existing actor remains held. A single successful spike does not replace per-admission and per-release checks. No spike observation creates a permit or stop proof.
3. Under TDD, implement owned SQLite permit, trust provenance, cross-operation uniqueness, complete indexed census and real capacity reservations with two-connection close/permit/revoke ordering and rollback/crash tests. Public launch remains disabled until host authority and broker are real. Old v2 inert streams and existing v1 streams retain their semantics. Implement a concrete isolated supervisor with the live one-shot capability, durable dispatch, manager-owner continuity and exact job correlation. Test orchestrator restart while it survives, and broker/manager death at every boundary; unresolved history must hold. Integrate the actual Worker pipe path with 512 KiB simultaneous input/output, slow readers/writers, separate stderr, EOF, cancellation, limits and descriptor-leak checks. Test using real manager behavior, not only mocked receipts.
4. Demonstrate on supported environments authorized producer control, manager identity and persistent cgroup containment. Test queued and delayed start, cancellation before method reply, JobRemoved before reply, job failure, unit replacement, manager-owner change, stop races, GC, cgroup disappearance/recreation, descendants and escape attempts. Prove the measured subtree remains meaningful and no sender can launch later. If any prerequisite is unavailable, leave the corresponding actor held and v2 disabled.
5. Integrate Provider sender, tool and Verifier only through the same owned evidence chain and current policy; unknown Provider outcome remains held and never resent. Complete C2b seal and Task 5 acceptance only after all actor kinds and the entire frozen census satisfy the design. Run focused integration and full regression, independently review implementation, and enable only after all acceptance criteria pass. No fixture, local manager sample, or unconsumed record counts as host-authenticated stop evidence.

## Review Focus

1. SQLite can open DB or sidecars through a different actual handle than a checked pathname; Task 3B tests rename/replacement and requires `handle_binding_unproven` rather than an eligible result.
2. A new trusted but stale process can start after a one-time inventory and install its own invisible TEMP reset trigger; Task 4A runs it against a real second connection and checks the gap is reported, not cured by a fingerprint.
3. A guard/DB state pair can be restored or crash between writes; Task 2B and Task 4B test every modeled cut and a real killed writer, forcing uncertainty and fresh epoch/rebuild.
4. Schema names, index keys and trigger SQL may be long, malformed or over budget; Task 1B preflights metadata length/type before materialization, including row-factory sentinels and existing TEMP schema.
5. A clean close or rollback does not prove an offline interval free of writes; Task 2C and Task 4C exercise old-process mutation after retirement and require new epoch, fresh rebuild or hold.

- Create `src/orchestrator/diagnostics/sqlite_continuity.py`: actual opt-in operator-facing consumer. `diagnose_store(path: Path, budget: ObservationBudget) -> DiagnosticReport` initially consumes real bounded schema observations and reports `storage_not_observed`; Task 3 extends the same consumer to combine actual storage observations. ## Task 2: Crash and lifecycle state model with explicit simulated guards

**Files:** create `_epoch_model.py` and `test_epoch_model.py`; create a test-only append-only fake guard under `tests/support/epoch_guard_fixture.py` if needed. Do not bind it to existing stores or permit paths. Its actual consumer is the local diagnostics CLI: an explicit `--simulate-journal PATH` mode parses a bounded, versioned local test trace and reports model transitions under a prominent `simulation_only` field; it never reads a real external guard as authoritative and cannot alter real epoch state. Accept only a controlled ordinary file in an approved local fixture/diagnostic directory, opened with an anchored no-follow strategy and verified with `fstat` as regular before reading; reject symlinks, hard links, FIFO, device, socket, stdin and unbounded streams. Preflight size before reading and use a total limit plus one-byte sentinel, per-record and record-count limits, and verify file identity/size has not changed; reject malformed, changing or oversized input. Never echo path or input content in errors. A potentially blocking open/read must run under a bounded, supervised helper with a deadline and exact-child cleanup; a timeout becomes a bounded `input_unavailable` result, never a successful simulation. Treat filesystems or kernel states where the helper cannot be promptly terminated as unsupported rather than claiming a universal hard deadline. Simulation input is mutually exclusive with database diagnosis.

**Interfaces:** `ModelState` values `ABSENT`, `ESTABLISHING`, `ACTIVE_SIMULATED`, `UNCERTAIN`, `RETIRED`; `EpochModel.start(instance: str, epoch: str)`, `mark_db_prepared(...)`, `activate_simulated(...)`, `retire(...)`, `recover(...)`. All methods validate bounded exact record shapes and sequence/generation; `ACTIVE_SIMULATED` exists to exercise a state machine, not to assert an actual guard exists. `recover_model` always returns `UNCERTAIN` for incomplete/unmatched, rollback/unknown commit, stale generation or malformed records; no record or constructor can create deployable authority.
